## copilot-server-agent 并发与多租户安全一轮整改

按 review 的 P0/P1 清单改完（review 结论：不同 session 已隔离，但同 session 多 request 未串行 + ownership 不可信）。

关键改动：
- **streaming lock**：SSE chat 改为在 `withSessionLock` 内 `sendAndWait()`（`send()` 只入队就返回，锁不到 agent loop）；事件监听器也移进锁内，避免并发请求互收 delta。新增 `sseFail` 收尾 + 客户端断开 `session.abort()` 当前 turn。
- **attach lock**：`getOrResumeSession` 加 `sessionAttachLocks`，解决并发首访双附着。
- **lifecycle lock**：disconnect / permanent delete 走同一 session lock；delete 用 `disconnectUnlocked` 避免重入死锁。
- **Session Registry**（新 `server/src/services/session-registry.ts`）：持久 JSON（原子写 + 串行 mutate），替代内存 owners Map；`assertOwnership` 统一归属校验，仅单租户下允许 legacy 认领。listSessions 按 owner 过滤。
- **工具授权**（新 `server/src/services/tool-policy.ts`）：取代 `approveAll`。read 放行 / write 限 workspace / shell 按 `COPILOT_BASH_POLICY`(默认 workspace) / MCP 限本次启用 server / URL 过 SSRF + allowlist / 未知 kind 拒绝。另加强制 `onPreToolUse` workspace 守卫（写类工具）。
- 路径判定坑：macOS `/var` → `/private/var` symlink，必须同时比对字面路径与 realpath，否则 workspace 内路径会被误判为越界。
- K8s：拆两个 PVC（去掉 subPath）、加 `fsGroup: 1000`、API 容器挂 runtime-state 卷放 registry。
- 版本：SDK 精确 pin 1.0.14，新增 `scripts/check-versions.mjs`（四处一致校验）与 `scripts/verify-agent-tools.mjs`（只认 tool.execution_start，防 #2356）。

验证：typecheck/build 通过；冒烟确认 create→chat(SSE error 帧正常收尾)→list→403(u2 访问 u1 会话)→permanent delete(registry 清空)。

## health 徽章 "disconnected" 语义修正

现象：刚打开页面徽章显示 `Copilot: disconnected`，但功能正常。
根因：`SessionService.getStatus()` 把「client 懒加载未创建」等同于 disconnected；`/api/health` 不碰 runtime（避免探针风暴），所以未发起会话前永远是 disconnected。
改法（用户选「两者都做」）：
- `getStatus()` 三态：`connected` / `idle` / `error`（idle = client 未创建，中性色，不是故障）；types.ts 与 client Health 类型同步。
- 新增 `SessionService.warmup()` + `COPILOT_WARMUP`（默认 true），server 启动后后台建连，不阻塞监听、失败只记日志。
- `HealthBadge` 三态渲染：connected 绿 / idle 灰（「未启动（首次会话时连接）」）/ error 黄 + 原因。
- `/api/debug` 配置块补充 registryPath / trustIdentityHeaders / bashPolicy。
验证：3s 内 healthy 变 connected 且日志「预热完成」；`COPILOT_RUNTIME_URL` 指向死端口时显示 error + ECONNREFUSED 原因。
