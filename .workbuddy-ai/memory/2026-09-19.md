# 2026-09-19

## Skill Flow / WorkflowRunner 三项加固（基于代码评审）

基线 commit `c43e74c`。评审结论：架构方向没问题，不需要推翻重做，改 failure semantics 与 step durability。

### 1. P0 runner 异常收尾（`server/src/workflow/runner.ts`）
- `runDetached()` 原来只 `console.error`，未预期异常会留下永远 `running` 的 execution。
- 改为：catch → `executions.get` → 非终态则 `executions.fail(id, err)`；连落 failed 都失败再 log。
- 需要 `import { isTerminal } from '../execution/types.js'`。
- 注意：`runSubagent`/`runGate` 自己 catch 了节点内失败（那是可路由出口），所以这条路径测试里不容易碰到，必须专门写用例（monkey-patch `executions.updateWorkflowState` 抛错来模拟）。

### 2. step durability：`WorkflowState.stepStatus`
- 新增 `WorkflowStepStatus = 'pending' | 'running' | 'waiting' | 'completed'`（optional，老数据按 pending）。
- `loop()` 里**先落 `running` 再执行节点**，执行完落 `{current: next, stepStatus: 'pending'}`；
  review/action 等人工落 `waiting`；`@stop`/`@end` 落 `completed`。
- 新增 `admitInterruptedStep()`：恢复时若 `stepStatus === 'running'` →
  `REPLAY_SAFE_NODE_TYPES = {agent, gate}` 允许重放（记 `workflow.step.interrupted` 审计）；
  `@action` **不重放**，落 failed 交人工核对（幂等键防不了"外部已生效但本地没记上"）。
- 新事件类型 `EVT.workflowStepInterrupted = 'workflow.step.interrupted'`。
- `workflow_state` 是 JSON blob 列，加字段不需要迁移。

### 3. validator 禁止同一出口多条 route
- 新增 `checkDuplicateOutcomes()`，code `route-outcome-duplicate`，节点与 `@flow` 的 `start` 都查。
- 原因：`findRoute()` 是 `routes.find(...)`，第二条静默失效。
- parser 已按 `on->to` 去重，所以"完全重复的同一条"不算歧义。

### 4. `@subagent` → `@agent`（旧名保留为别名）
- 语义澄清：它跑的是**当前 session 的又一次 agent turn**（`runExecutionTurn`），不是真正的 subagent 委派。
- parser 用 `BLOCK_ALIASES = { subagent: 'agent' }` 归一化，下游只认 `agent`。
- `FlowNodeType` 里 `'subagent'` 已移除；`runSubagent` 改名 `runAgent`。
- **不要动** `subagent.*` SDK 生命周期事件（`agent-runner.ts` / `agent-events.ts` / `Chat.tsx` / SSE `subagent` 帧）—— 那是另一回事。

## 业务角色模型：Role / Entra Group / 授权解析（按设计提案全量实现）

用户决策：**按提案全量实现** + **group → 角色解析放在网关**（服务端不调 Microsoft Graph）。

### 新增 `server/src/identity/`
- `business-roles.ts`：RoleRegistry。`BusinessRole { id, name, groups[], match: ANY|ALL }`，
  `resolveRolesForGroups()` 是**同步纯函数**（无网络/无 token）。
  内置角色只登记 id 不登记 group；映射由 `COPILOT_BUSINESS_ROLES`（JSON 数组）配置，
  配错启动即失败。没配 groups 的角色谁都拿不到（fail-closed）。
- `authorization-service.ts`：`resolveRoles(principal)` = `principal.roles` ∪ group 映射，
  同步、去重、排序。**同步是刻意的** —— 它被 `HumanTaskService.withTaskLock()` 临界区包着。

### 身份
- `Principal.groups?: string[]`（Entra group **object ID**），来自 `x-user-groups`（网关注入，最多 200 条）。
- `principalFromHeaders` 未开启 `COPILOT_TRUST_IDENTITY_HEADERS` 时 groups=[]。

### 授权接线（两处，都要用解析后的角色）
- `ApprovalService.assertEligible`：拿 `resolveRoles(principal)` 比 `policy.eligibleRoles`。
- `HumanTaskService.actorRoles()` → `isAssignee` / `list`（"我的任务"可见性）。
  **漏了后者 = 走 AD group 的人看不到自己的待办。**
- `isAssignee(task, actor)` 签名从 `Principal` 改成 `{ userId, roles }`（已解析角色）。

### SKILL.md 保留属性
- 只有 `@review`（role/strategy/required/exclude）与 `@action`（role）支持，**必须写在正文最前面**。
- parser 只做词法（属性区切分 + 名字检查），validator 做值校验。
- 属性区判定："最前面连续一段 `name: value`"；段内已认领到属性时，认不出的名字报
  `block-attr-unknown`（抓 `roles:` 拼错），否则整段当正文（`Note: ...` 开头不误伤）。
- 新 issue code：`block-attr-unsupported` / `block-attr-unknown` / `block-attr-duplicate` /
  `attr-invalid` / `role-missing` / `review-missing-role`。
- `role` 形态校验在**小写化之前**做（`BUSINESS_ROLE_ID` 要求全小写），
  这样 `APP-FIL-Compliance-Reviewer` 这类 AD 组名会被直接拒掉。

### 语义要点
- `@review role:` **覆盖**注册表 `eligibleRoles`；两边都没有 → `review-missing-role`。
- `@action role:` 与该 actionType 的 `ApprovalPolicy.eligibleRoles` **取交集**，空交集 → deny。
  只能收窄不能放宽；声明了 role 的动作**不走 `COPILOT_AUTO_APPROVE_ACTIONS`**。
- 内置角色 id 改名：`compliance-reviewer` → `compliance.reviewer`，`investment-reviewer` → `investment.reviewer`。

`npm --prefix server run typecheck` ✅ / `npm --prefix server test` → **159/159** ✅（新增 21 个用例）

## 第三轮：安全加固（同日，接上一节）

⚠️ **上一节"`@review role:` 覆盖注册表"已作废** —— 那是可以放宽授权的漏洞，本轮改成交集。

### 1. 四个属性一律只能更严（`@review`）
- 注册表 `FlowReview` 成为**权威基策略**：`eligibleRoles` 必填，新增 `allowInitiator`（默认 false）。
- `role` → 与基策略取**交集**；`strategy` → 只能 ANY→ALL；`required` → 只能 ≥ 基策略；
  `exclude: none` → 基策略不允许自批时报错。
- 新 issue code：`role-not-allowed` / `attr-widens`。
- 运行时 `reviewPolicyFor()` 再 clamp 一次（不信任校验器，fail-closed）。
- 注册表查找回调从 `reviewRoles()` 换成 `reviewPolicy()`（返回 `ReviewBasePolicy`），
  `undefined` = 未登记，空 `eligibleRoles` = 登记了但没人有资格（→ `review-missing-role`）。

### 2. `@gate` 出口静态声明
- `FlowGate.outcomes` **必填**（注册时校验非空）；`flowRegistryLookup.gateOutcomes()`。
- 新 issue code：`gate-outcome-unrouted`（声明了但没 route）/ `gate-outcome-unknown`（route 了但没声明）。

### 3. `@agent` 能力边界（`workflow/capability.ts`，新文件）
- 上限 `COPILOT_WORKFLOW_AGENT_TOOLS`（默认 `read,write,url`，**不含 mcp/shell** —— 那两条是绕开
  `@action` 审批的路径）。`@agent tools:` 只能收窄（`agent-tools-widens`）。
- 进程内 `Map<sessionId, AgentCapability>`，`tool-policy.ts` 的 `ToolPolicyContext.capability`
  是**回调**（建会话时还不知道节点），权限请求时现取；第 0 层判定，只收窄不替代原检查。
- `session-service.ts` 的 `policyCtx` 注入 `capability: () => agentCapabilityFor(sessionId)`。

### 4. `@agent` 完成契约
- `@agent output: <id>` + 服务端 `registerFlowOutput({name, description, validate({content})})`。
- 契约没过 → `fail` 出口（可路由）。内置示例 `non-empty`。
- `COPILOT_WORKFLOW_REQUIRE_AGENT_OUTPUT=true` 时强制每个 `@agent` 都声明（`agent-output-missing`），默认关。
- 新 issue code：`registry-missing-output` / `agent-output-missing` / `agent-tools-widens`。

### 5. 单写者 / CAS
- 新列 `agent_execution.workflow_version integer not null default 0`
  （migration `004_workflow_single_writer.sql` + `sqlite-schema.ts` CREATE TABLE + COLUMN_UPGRADES）。
- ⚠️ **`workflow_version` 不在 `sql-repository.ts` 的 `COLUMNS` 里** —— 只由 CAS 语句抬高，
  否则一次 `addUsage()` 的整行 upsert 就会把它写回旧值。
- 新仓储方法 `compareAndSwapWorkflowState(executionId, expectedVersion, workflow)`；
  `ExecutionService.updateWorkflowState(id, state, expectedVersion?)` 返回
  `WorkflowStateWrite = {ok:true,version} | {ok:false,conflict:true,current?}`。
- runner 内 `StateWriter` 串版本号；冲突 → 留痕 `workflow.write.conflict` + **停止推进**，
  **绝不落 failed**（否则会打死别人正在跑的流程）。
- 进程内 `withExecutionLock(executionId, fn)`（promise 链，不是"忙就丢弃"）。

### 6. 人工任务回调绑定
- 四件事全对才续跑：`waitingTaskId === task.taskId`、`state.current === marker.nodeId`、
  `stepStatus === 'waiting'`、`rec.status === 'waiting_for_approval'`。
- 任一条不成立 → `workflow.resume.rejected` 事件 + 不动状态。
- **顺带修掉一个 bug**：workflow 任务过期/取消走的是编排器回调（不经过
  `ExecutionService.onHumanTaskResolved`），原实现只写事件不落终态 → execution 永远卡在
  waiting_for_approval。新增 `settleUnresumable()` 落 expired/cancelled 终态。

### 7. 接口边界拆分
- `workflow/definition-provider.ts`（新）：`FlowDefinitionProvider` + `SkillFileDefinitionProvider`
  （`load` / `reload`，`reload` 校验 sourceHash，issue code `skill-changed`）。
- `workflow/runtime.ts`（新）：`FlowNodeRuntime` + `DefaultFlowNodeRuntime`
  （`runAgent` / `runGate` / `runAction` / `openReview`），能力边界与完成契约在这里落地。
- `runner.ts` 只剩状态机：推进 / 落库 / 路由 / 人工任务接回。
- `WorkflowTurnRunner` 类型从 runner.ts 移到 runtime.ts（runner 仍 re-export）。
